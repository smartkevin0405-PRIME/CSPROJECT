# 하드웨어 요약

부품 도착 전 초안이다. 실물로 확인할 항목은 맨 아래에 있다.

## 전원

- 보드: USB-C 5V (시연 때는 5V 2A 충전기나 보조배터리)
- 화면 실드: 5V, 3.3V, GND를 모두 연결한다. 실드의 RESET 핀은 아두이노 리셋이라 비워 둔다
- RC522: 3.3V. 전원에는 분압 저항을 쓰지 않는다. 5V에 꽂지 않는다
- PIR, DHT11: 5V

## 핀 배치 (2026-11-26판, 헤더 20핀 모두 사용)

| 보드 핀 | 연결 | 비고 |
| --- | --- | --- |
| D0 | DHT11 DATA | 모듈 표기 S, +, − 순서 확인 |
| D1 | 문 센서 MC-38 | 내부 풀업, 다른 선은 GND |
| D2~D7 | 화면 LCD_D2~D7 | 바로 연결 |
| D8, D9 | 화면 LCD_D0, LCD_D1 | 바로 연결 (순서 주의) |
| D10 | RC522 SDA | 분압 |
| D11 | RC522 MOSI | 분압 |
| D12 | RC522 MISO | 바로 연결 (74HCT125N이 오면 그 칩을 거침) |
| D13 | RC522 SCK | 분압 |
| A0~A4 | 화면 LCD_RD, LCD_WR, LCD_RS, LCD_CS, LCD_RST | 바로 연결 |
| A5 | PIR OUT | 아날로그로 읽음 (`PIR_THRESHOLD` 300) |

RC522 RST는 보드에 연결하지 않고 3.3V에 올린다(10kΩ 풀업 또는 3.3V 직결). **GND에 꽂으면 RC522가 꺼져서 응답하지 않는다.**

## 전압 변환

- 화면 실드: 기판에 변환 칩(U1, U2)이 있어 분압하지 않는다
- 보드 → RC522 (D10, D11, D13): 보드 핀 → 470Ω → (여기서 RC522로) → 1kΩ → GND. 약 3.4V. 1kΩ·2kΩ도 된다
  - 220Ω·1kΩ은 쓰면 안 된다. 방향에 따라 4.1V(RC522 손상 위험)나 0.9V(신호 인식 안 됨)가 된다
- RC522 MISO → D12, PIR → A5: 칩 없이 바로 연결해도 동작했다(2026-11-26). 74HCT125N이 오면 배선도대로 넣는다

## 화면

- 칩: HX8357B. ILI9486, ILI9488, ST7796, HX8357B 네 드라이버를 차례로 시험해 HX8357B에서 화면이 떴다. ID 레지스터 0xBF에서 `8357`이 읽힌다
- 라이브러리: Arduino_GFX의 `Arduino_SWPAR8`(소프트웨어 8비트 병렬) + `Arduino_HX8357B`. MCUFRIEND_kbv는 UNO R4를 지원하지 않는다(컴파일 오류)
- 소프트웨어 병렬이라 화면 전체 칠하기는 느리다. 코드는 부팅 때만 전체를 칠하고, 그 뒤로는 바뀐 글자 자리만 다시 그린다

## 구매 품목

구매표 시트가 기준이다. 바뀐 점만 적는다 (2026-11-16, 서보 제외는 2026-11-24).

- 화면: THL-CD07 대신 G마켓 3.5인치 IPS ILI9488 SPI 480×320, "01 IPS 3.5 No Touch9488" 옵션 22,800원 무료배송. 상세정보 일부에 320×240 표기가 섞여 있다
- 추가: 74HCT125N DIP 660원 (디바이스마트), 0.1µF 세라믹, 10kΩ 1개
- 분압 저항: 1kΩ·2kΩ 각 6개로 줄었다
- 제외: TXS0108E, 4채널 로직레벨 컨버터 (74HCT125N으로 대신)
- 제외 (2026-11-24): 서보를 쓰지 않기로 해서 SMPS 5V 2A 어댑터, DC잭 2P 터미널 변환 어댑터, 1000µF 전해 콘덴서가 필요 없다. 키트의 SG90도 쓰지 않는다. 앞으로 3시간 날씨는 화면의 `NEXT 3H`로만 보여 준다

## 이동 시간 모듈과의 약속

`SmartEntrance/travel_iface.h`(v0.2)가 약속이고, `SmartEntrance/travel_link.cpp`가 이를 이동 시간 모듈(TravelLearn) 호출로 바꾼다.

- 등록된 카드를 태그한 뒤 120초 안에 문이 열리면 `travelOnDeparture()`로 출발 이벤트를 한 번 넘긴다. 출발 후 90초 안에 같은 사람이 다시 태그하면 `travelOnCancel()`
- 번호: 모듈과 폰 앱의 사용자 번호는 `USERS` 배열 위치+1, 정류장 번호는 `STOPS` 배열 위치+1이다. `Stop.key`는 메인 코드 안에서만 쓰는 이름이고 모듈에 넘기지 않는다
- 폰 앱의 정류장 n번은 `STOPS`의 n번째와 같은 정류장이어야 한다. 학습을 시작한 뒤 순서를 바꾸면 기록이 섞인다
- 출발 신호의 정류장은 0(모름)으로 보낸다. 폰이 그 사용자의 정류장을 모두 감시한다
- 날씨: 화면 `NEXT 3H`는 앞으로 3시간 중 처음 나온 강수형태, 학습에는 가장 가까운 예보 시각의 강수형태(`WeatherInfo.nowPty`)를 쓴다
- 보드의 Wi-Fi 연결과 재연결(끊긴 채 30초마다)은 메인 코드가 한다. 모듈의 서버(8080)는 다시 열 필요가 없다
- EEPROM 0~4095번지는 모듈이 쓴다. 메인 코드는 EEPROM을 쓰지 않는다

## 실물로 확인한 것 (2026-11-26)

- DHT11(D0) 21°C 43%, PIR(A5) 감지·끝, 문 센서(D1) OPEN·CLOSED 정상
- RC522 버전 0x82 (호환 칩 값). 카드 번호가 매번 같게 읽힘 (`EB 02 EC 05`, `0D 77 42 06`)
- 화면 HX8357B 드라이버로 표시 확인
