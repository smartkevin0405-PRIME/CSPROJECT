# 하드웨어 요약

부품 도착 전 초안이다. 실물로 확인할 항목은 맨 아래에 있다.

## 전원

- 보드: USB-C 5V (시연 때는 5V 2A 충전기나 보조배터리)
- 서보: 별도 5V 어댑터 → DC 터미널. 어댑터 +는 서보 빨간 선에만, −는 서보 갈색 선과 보드 GND에 함께 연결
- 5V 어댑터를 보드 배럴잭(VIN 6~24V)에 꽂지 않는다
- RC522: 보드 3.3V. 전원에는 분압 저항을 쓰지 않는다
- 화면: VCC·LED 전원은 받은 모듈의 표기를 보고 정한다. 배선도는 VCC 5V, LED 3.3V로 그려 두었다 (미확정)
- 74HCT125N: 14번 5V, 7번 GND, 두 핀 가까이에 0.1µF 세라믹
- 서보 전원선 가까이에 1000µF 전해 콘덴서

## 핀 배치 (헤더 20핀 중 11핀 사용)

| 보드 핀 | 용도 | 전압 처리 |
| --- | --- | --- |
| D2 | PIR 출력 | 74HCT125 2채널(5번 입력 → 6번 출력)로 5V 변환, `digitalRead` |
| D3 | 서보 신호 | 5V 그대로 |
| D4 | DHT11 데이터 | 5V 그대로 |
| D5 | 문 열림 센서 MC-38 | 내부 풀업 |
| D7 | 화면 RESET | 분압 |
| D8 | 화면 DC/RS | 분압 |
| D9 | 화면 CS | 분압 |
| D10 | RC522 SDA(SS) | 분압. 분압 전 신호는 74HCT125 1번(1OE)에도 연결 |
| D11 | SPI MOSI → 화면 SDI, RC522 MOSI | 분압 1개 공유 |
| D12 | SPI MISO ← RC522 MISO | 74HCT125 1채널(2번 입력 → 3번 출력). 화면 SDO는 비움 |
| D13 | SPI SCK → 화면 SCK, RC522 SCK | 분압 1개 공유 |

RC522 RST는 보드에 연결하지 않고 10kΩ으로 3.3V에 올린다. 코드는 `MFRC522(ss, MFRC522::UNUSED_PIN)`으로 소프트웨어 리셋을 쓴다.

비어 있는 핀: D0, D1, D6, A0~A5

## 전압 변환

- 보드 → 화면·RC522 (6개: D7, D8, D9, D10, D11, D13): 보드 핀 → 1kΩ → (여기서 모듈로) → 2kΩ → GND. 약 3.33V. 1kΩ 6개, 2kΩ 6개, 가능하면 오차 1%
- RC522 MISO → 보드: 74HCT125N. 5V 전원에서 HIGH 입력을 2.0V 이상으로 받으므로 3.3V 출력을 5V로 올린다. 1번(1OE)이 LOW일 때만 출력하므로 D10이 RC522를 고를 때만 D12에 연결된다
- PIR 출력 → 보드: 같은 칩의 2채널. 4번(2OE)은 GND로 항상 켠다
- 남는 3·4채널: 입력(9, 12번)은 GND, 출력 켜기(10, 13번)는 5V, 출력(8, 11번)은 비움
- 74HC125(CT 없는 것)와 헷갈리지 않는다

## SPI 속도

- 화면: 500kHz에서 시작 (`config.h`의 `TFT_SPI_HZ`). 이 속도에서는 화면 전체를 한 번 칠하는 데 약 7초가 걸린다(480 × 320 × 3바이트). 그래서 전체 칠하기는 부팅 때 한 번만 하고, 그 뒤에는 그린 글자 자리만 지우고 바뀐 글자만 다시 그린다. 깨짐이 없으면 4MHz, 8MHz 순서로 올려 본다
- RC522: MFRC522 라이브러리가 4MHz로 고정해 둔다. 스케치에서 바꾸지 못한다. 분압 상태에서 읽기 오류가 나면 라이브러리의 `MFRC522_SPICLOCK` 값을 낮춘 복사본을 써야 한다

## 구매 품목

구매표 시트가 기준이다. 바뀐 점만 적는다 (2026-11-16).

- 화면: THL-CD07 대신 G마켓 3.5인치 IPS ILI9488 SPI 480×320, "01 IPS 3.5 No Touch9488" 옵션 22,800원 무료배송. 상세정보 일부에 320×240 표기가 섞여 있다
- 추가: 74HCT125N DIP 660원 (디바이스마트), 0.1µF 세라믹, 10kΩ 1개
- 분압 저항: 1kΩ·2kΩ 각 6개로 줄었다
- 제외: TXS0108E, 4채널 로직레벨 컨버터 (74HCT125N으로 대신)

## 이동 시간 모듈과의 약속

`SmartEntrance/travel_iface.h`(v0.2)가 약속이고, `SmartEntrance/travel_link.cpp`가 이를 이동 시간 모듈(TravelLearn) 호출로 바꾼다.

- 등록된 카드를 태그한 뒤 120초 안에 문이 열리면 `travelOnDeparture()`로 출발 이벤트를 한 번 넘긴다. 출발 후 90초 안에 같은 사람이 다시 태그하면 `travelOnCancel()`
- 번호: 모듈과 폰 앱의 사용자 번호는 `USERS` 배열 위치+1, 정류장 번호는 `STOPS` 배열 위치+1이다. `Stop.key`는 메인 코드 안에서만 쓰는 이름이고 모듈에 넘기지 않는다
- 폰 앱의 정류장 n번은 `STOPS`의 n번째와 같은 정류장이어야 한다. 학습을 시작한 뒤 순서를 바꾸면 기록이 섞인다
- 출발 신호의 정류장은 0(모름)으로 보낸다. 폰이 그 사용자의 정류장을 모두 감시한다
- 날씨: 다이얼은 앞으로 3시간 중 처음 나온 강수형태, 학습에는 가장 가까운 예보 시각의 강수형태(`WeatherInfo.nowPty`)를 쓴다
- 보드의 Wi-Fi 연결과 재연결(끊긴 채 30초마다)은 메인 코드가 한다. 모듈의 서버(8080)는 다시 열 필요가 없다
- EEPROM 0~4095번지는 모듈이 쓴다. 메인 코드는 EEPROM을 쓰지 않는다

## 실물로 확인할 것

- 받은 화면의 실제 해상도(480×320인지), 핀 순서, 전원 규격(VCC 5V 가능 여부, LED 핀)
- UNO R4 WiFi + Arduino_GFX + 이 모듈 조합의 동작
- 분압 상태에서 화면과 RFID 동시 동작, 500kHz에서 화면 깨짐 여부와 올릴 수 있는 속도
- RC522를 4MHz(라이브러리 고정)로 읽을 때 오류 여부
- 74HCT125N을 거친 MISO와 PIR 신호
- 키트 서보의 모델과 동작 전류
