# 하드웨어 요약

부품 도착 전 초안이다. 실물로 확인할 항목은 맨 아래에 있다.

## 전원

- 보드: USB-C 5V (시연 때는 5V 2A 충전기나 보조배터리)
- 서보: 별도 5V 2A 어댑터 → DC 터미널. 어댑터 +는 서보 빨간 선에만, −는 서보 갈색 선과 보드 GND에 함께 연결
- 5V 어댑터를 보드 배럴잭(VIN 6~24V)에 꽂지 않는다
- TFT의 VCC는 보드 5V, LED(백라이트) 핀은 보드 3.3V
- 서보 전원선 가까이에 1000µF 전해 콘덴서

## 핀 배치 (헤더 20핀 중 12핀 사용)

| 보드 핀 | 용도 | 전압 처리 |
| --- | --- | --- |
| D2 | 문 열림 센서 MC-38 | 내부 풀업 |
| D3 | 서보 신호 | 5V 그대로 |
| D4 | DHT11 데이터 | 5V 그대로 |
| D5 | RC522 RST | 분압 |
| D6 | RC522 SDA(SS) | 분압 |
| D7 | TFT RESET | 분압 |
| D8 | TFT DC/RS | 분압 |
| D10 | TFT CS | 분압 |
| D11 | SPI MOSI → TFT SDI, RC522 MOSI | 분압 1개 공유 |
| D12 | SPI MISO ← RC522 MISO | 직결. TFT SDO는 비움 |
| D13 | SPI SCK → TFT SCK, RC522 SCK | 분압 1개 공유 |
| A0 | PIR 출력 | 직결, analogRead로 판정 |

비어 있는 핀: D0, D1, D9, A1~A5

## 분압

보드는 5V 로직, TFT와 RC522는 3.3V 신호다. 보드에서 나가는 신호 7개(D5, D6, D7, D8, D10, D11, D13)는
보드 핀 → 1kΩ → (여기서 모듈로) → 2kΩ → GND 로 낮춘다. 1kΩ 7개, 2kΩ 7개가 필요하다.

## 이동 시간 모듈과의 약속

`SmartEntrance/travel_iface.h`(v0.2)가 약속이고, `SmartEntrance/travel_link.cpp`가 이를 이동 시간 모듈(TravelLearn) 호출로 바꾼다.

- 등록된 카드를 태그한 뒤 120초 안에 문이 열리면 `travelOnDeparture()`로 출발 이벤트를 한 번 넘긴다. 출발 후 90초 안에 같은 사람이 다시 태그하면 `travelOnCancel()`
- 번호: 모듈과 폰 앱의 사용자 번호는 `USERS` 배열 위치+1, 정류장 번호는 `STOPS` 배열 위치+1이다. `Stop.key`는 메인 코드 안에서만 쓰는 이름이고 모듈에 넘기지 않는다
- 폰 앱의 정류장 n번은 `STOPS`의 n번째와 같은 정류장이어야 한다. 학습을 시작한 뒤 순서를 바꾸면 기록이 섞인다
- 출발 신호의 정류장은 0(모름)으로 보낸다. 폰이 그 사용자의 정류장을 모두 감시한다
- 날씨: 다이얼은 앞으로 3시간 중 처음 나온 강수형태, 학습에는 가장 가까운 예보 시각의 강수형태(`WeatherInfo.nowPty`)를 쓴다
- 보드의 Wi-Fi 연결과 재연결(끊긴 채 30초마다)은 메인 코드가 한다. 모듈의 서버(8080)는 다시 열 필요가 없다
- EEPROM 0~4095번지는 모듈이 쓴다. 메인 코드는 EEPROM을 쓰지 않는다

## 실물로 확인할 것

- THL-CD07의 핀 순서, 헤더 납땜 여부, 화면 창 치수
- UNO R4 WiFi에서 ILI9488 SPI 동작과 속도
- 저항 분압 상태에서 SPI 안정성, RC522 MISO 인식
- PIR을 A0에서 읽을 때의 기준값
- 키트 서보의 모델과 동작 전류
