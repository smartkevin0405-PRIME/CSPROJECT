# 이동 시간 학습 모듈 (외출 준비 스마트 현관판)

현관판이 문 열림을 알리면 폰이 정류장까지 걸린 시간을 재고, 귀가 후 현관판에 돌려준다.
현관판은 사용자·정류장·날씨·시간대별 평균과 편차를 쌓아 `여유 시간 = 버스 도착까지 남은 시간 − 예상 이동 시간 − 안전 여유`를 계산한다.
외부 서버와 GPS 모듈 없이 집 Wi-Fi와 폰의 위치 기능만 쓴다.

이 폴더는 **Android 앱**과 **아두이노의 폰 통신·학습 모듈**만 담는다. 센서·화면·날씨/교통 API·메인 프로그램은 `../entrance-board/SmartEntrance`에 있고, 그 안의 `travel_link.cpp`가 이 모듈(`arduino/TravelLearn`)을 메인 프로그램에 연결한다(2026-11-13).

## 가장 빠른 확인 순서

1. **PC만으로**: `./run-all-tests.sh` (Linux/macOS/WSL, g++·JDK·Python 3)
2. **폰 + PC**: PC에서 `python tools/virtual_board.py` 실행 → 폰에 APK 설치 → `docs/Android17_제약과_초기설정.md` 4장대로 설정 → 가상 현관판 콘솔에서 `depart 1`
3. **보드 + PC**: 예제 `VirtualBoard`를 UNO R4 WiFi에 올림 → PC에서 `python tools/virtual_phone.py --board <보드 IP>:8080`
4. **보드 + 폰**: 폰 앱의 현관판 IP를 보드 주소로 바꾸고 직렬 모니터에서 `d 1`
5. `docs/시험목록.md`의 A~H

공유 키 만들기: `python -c "import secrets; print(secrets.token_hex(16))"` → 보드의 `arduino_secrets.h`와 폰 앱에 같은 값.

## 앱 설치와 빌드

2026-11-13 리뷰 수정은 소스에 반영했다. `apk/TravelLearn-debug.apk`는 수정 전 빌드이므로, 새 동작을 쓰려면 아래 방법으로 소스에서 APK를 다시 빌드해야 한다.

- 설치: `apk/TravelLearn-debug.apk`를 폰으로 옮겨 연다. "출처를 알 수 없는 앱 설치"를 허용해야 하고 Play 프로텍트 경고가 뜰 수 있다.
- 권장 빌드: Android Studio에서 `android/` 폴더를 연다. Android 17(API 37) SDK와 AGP 9.3 이상이 필요하다. Studio가 Gradle·플러그인 버전 변경을 권하면 따른다.
- 이 APK는 Android Studio가 아니라 `android/build-manual.sh`(우분투의 aapt2·dalvik-exchange·apksigner)로 만들었다. 설치나 실행에 문제가 있으면 Android Studio 빌드로 바꾼다. 서명 키가 달라지므로 그때는 기존 앱을 지우고 설치한다(폰에 쌓인 기록은 지워진다. 현관판의 통계는 남는다).
- 로컬 네트워크 권한 문제로 통신이 막히면 `android/app/build.gradle`의 `targetSdk`를 36으로 낮춰 빌드하는 우회가 있다.

### 2026-11-13 리뷰 수정 검증

- PC 자동 시험 7단계 전부 통과. 출발 시각 보존, API 장애 중 출발, 정류장별 ETA, 수동 정류장 선택, 등록 재시도, 컴파일 실패 시 중단을 추가 확인했다.
- Android 앱 전체 Java 소스(UI·서비스 포함)는 API 35 `android.jar`와 임시 R 기호로 컴파일했다. 이번 변경은 API 35 이하 API만 추가 사용하며, 이것은 API 37 리소스 링크·APK 패키징 검증을 대신하지 않는다.
- 이번 수정 후 보드용 컴파일·실기기·새 APK 빌드는 미확인이다. 위 기존 보드·APK 빌드 결과와 메모리 수치는 수정 전의 기록이다.
- 수동 도착: 이름 또는 좌표가 설정된 정류장만 사용한다. 여러 곳이면 앱에서 고르고, 한 곳이면 그곳에 저장한다. 선택 화면을 열었던 시각을 도착 시각으로 쓰며, 설정된 정류장이 없으면 기록하지 않는다.
